VoiceJournal Wireframes and Build Plan

This pass-3 artifact combines refined wireframes with an implementation plan in one self-contained review deck. The design direction for this pass is simple: make the archive feel more grounded, make spoken entries easier to finish, and keep every screen readable in user language while still fitting macOS, Windows, and Linux.

Pass 3 Intent

  • Keep the full month view as the emotional center of the archive.
  • Make the end of a spoken session obvious with a visible finish action.
  • Preserve archive context when opening and closing entries.
  • Promote photos from side attachments to a shaped part of the journal page.
  • Give Settings one clear readiness summary before any detailed rows.

Build Plan Summary

  • Start with validation spikes that can still invalidate the build approach.
  • Build shared foundations before visual polish.
  • Ship one vertical slice first: Home to Session to Review to Save.
  • Add archive continuity, photo hierarchy, and platform fit after the first working loop.
  • Finish with cross-platform QA, accessibility, and release readiness checks.

Pass 3 Principles

Calm Archive

The month view remains the main browsing surface. It should feel like opening a private record, not querying a tool.

Full month view Context preserved Quiet density signals

Clear Finish

The user should always know how to move from speaking into the written draft. Ending the entry should never require guesswork.

Finish Entry Visible action No hidden path

Plain Language

The main app experience talks about reflection, writing, privacy, and progress. It does not expose internal mechanics or tool jargon.

User goals No diagnostics tone Credible privacy copy

Platform Chrome Direction

macOS

Use the most restrained chrome. The content title matters more than the app name, and the toolbar stays sparse.

Unified toolbar Content-first title One strong trailing action

Windows

Keep title bar and command surface clearly separated. Commands stay predictable, and archive spacing remains generous.

Command rhythm 24 px margins Clear back path

Linux

Preserve left, center, and right balance in header bars. Keep drag space visible and avoid heavy custom chrome.

Header bar fit Flat controls Minimal density

Pass 3 Decisions To Lock

Archive Continuity

  • Home keeps full month view at all times.
  • Opening and closing Viewer preserves selected day and scroll position.
  • Calendar cells can show multiple-entry density without turning into analytics.

Finish Path

  • Session gets a visible Finish Entry action in the main layout.
  • Review uses state-based completion language.
  • Primary actions always describe the user's next outcome.

Surface Tone

  • Photos are part of the journal page, not an afterthought.
  • Settings begins with readiness, not subsystem detail.
  • Lightbox removes persistent instructional copy.

Implementation Plan

Build sequencing should reduce risk first, then prove the product loop, then add the archive and media refinements that make the experience feel complete.

0

Validation Spikes

  • Confirm Gemma 3n loading on the pinned runtime.
  • Confirm bundled assets load correctly in dev and packaged builds.
  • Confirm macOS unified toolbar behavior with the required command density.
  • Confirm motion provider behavior across supported platforms.
  • Confirm the Silero VAD ONNX contract exactly matches the designed flow.
1

Shared Foundations

  • Configuration, paths, and bundled assets.
  • Single-instance protection and startup safety.
  • Local repository, SQLite setup, and search support.
  • Model source registry and downloader behavior.
  • Worker signal infrastructure and theme/template system.
2

Voice Runtime

  • Audio capture and resampling.
  • VAD worker and session resets.
  • Transcription pipeline.
  • TTS engine and playback worker.
  • LLM engine for questions, prose, and metadata.
3

First Vertical Slice

  • Home with calendar, recent list, and New Entry action.
  • Session with visible Finish Entry path.
  • Review with editable draft and save behavior.
  • Save entry and return the user to Home with updated content.
  • Do not widen scope before this loop works end to end.
4

Archive And Viewer

  • Preserve month, day, and list context when opening entries.
  • Build the Viewer with contextual back behavior.
  • Implement month and year stepping with stable selection.
  • Add the richer calendar markers defined in pass 3.
5

Photos, Settings, Lightbox

  • Move photo hierarchy fully into Review and Viewer.
  • Add photo captions and ordering behavior.
  • Add Settings readiness summary before detail rows.
  • Implement the simplified lightbox with quiet overflow actions.
6

Platform Fit And QA

  • Lock Home, Review, and Viewer toolbar layouts per OS family.
  • Validate shortcuts, dialogs, and navigation behavior.
  • Run accessibility and contrast checks on key trust cues.
  • Finalize packaging, startup, and offline-readiness behavior.

Acceptance Gates

Archive Gate

  • The user can browse multiple years while staying in a full month view.
  • The user can open an entry and return to the same archive position.
  • Day cells communicate presence and density without becoming noisy.

Session Gate

  • The user can always tell how to finish a spoken entry.
  • The central state remains visually dominant over header controls.
  • Photo add remains visible but not disruptive.

Surface Gate

  • Review completion language stays user-centered.
  • Settings communicates readiness before details.
  • Lightbox feels immersive without tutorial-style copy.
